# AutumnApply 安装与使用指南

本文面向第一次使用 GitHub、Node.js 或 Chrome 扩展的用户。AutumnApply 目前由两部分组成：

- **Chrome 扩展**：工作台、个人资料、岗位搜索、申请准备和招聘表单辅助；
- **本机服务**：简历文件解析、Word 导出和可选的 BYOK AI 调用，只监听 `127.0.0.1:43127`。

它不是已经签名的桌面安装包，因此第一次使用时需要手动在 Chrome 中加载一次扩展。之后通常只需在电脑重启后再次运行启动器。

## 1. 开始前准备

两个平台都需要：

1. **Google Chrome**；
2. **Node.js 20 或更高版本**，建议从 [Node.js 官网](https://nodejs.org/)安装 LTS 版本；
3. 可以访问 GitHub 和公开招聘网站的网络。

安装 Node.js 后，可以在终端中运行以下命令确认版本：

```bash
node --version
```

看到 `v20`、`v22` 或更高版本即可。如果系统提示找不到 `node`，请完成 Node.js 安装并重新打开终端或文件管理器。

## 2. 获取项目

### 方式 A：下载 ZIP，适合普通用户

1. 打开 AutumnApply 的 GitHub 仓库；
2. 点击绿色的 **Code** 按钮；
3. 选择 **Download ZIP**；
4. 下载完成后，把 ZIP 完整解压到一个长期保留的文件夹；
5. 不要直接在压缩包预览窗口里运行启动器，也不要在加载扩展后移动该文件夹。

### 方式 B：使用 Git，适合需要持续更新的用户

```bash
git clone https://github.com/CalBill/autumn-apply.git
cd autumn-apply
```

## 3. Windows 安装

### 3.1 一键启动

1. 打开已经解压或克隆的 `autumn-apply` 文件夹；
2. 双击 **`AutumnApply.cmd`**；
3. 第一次运行时，启动器会检查 Node.js 版本并运行 `npm install`，因此可能需要几分钟；
4. 随后它会构建扩展、启动本机服务，并打开 `dist\extension` 文件夹；
5. 如果 Chrome 安装在标准位置，启动器还会打开 `chrome://extensions`。

如果公司电脑的安全策略禁止运行批处理文件，请不要关闭或绕过安全软件。可以先检查脚本内容，并在允许的命令提示符或 PowerShell 中进入项目目录后运行：

```powershell
npm install
npm run launch
```

### 3.2 在 Chrome 中加载扩展

1. 在 Chrome 地址栏输入 `chrome://extensions`；
2. 打开右上角的 **开发者模式**；
3. 点击 **加载已解压的扩展程序**；
4. 选择项目中的 `dist\extension` 文件夹；
5. 在 Chrome 工具栏的拼图图标中找到 AutumnApply，并选择固定。

如果启动器提示没有自动找到 Chrome，请手动完成以上步骤。启动器仍然会打开正确的扩展目录。

### 3.3 Windows 上的 AI 密钥

如果启用 BYOK AI，API Key 会由本机服务通过 PowerShell 交给 Windows DPAPI，并使用**当前 Windows 用户**加密。磁盘上保存的是密文，其他 Windows 账户无法直接解密；扩展不会读取或重新显示密钥。普通配置和加密密文位于 `%APPDATA%\AutumnApply`。

## 4. macOS 安装

### 4.1 一键启动

1. 打开已经解压或克隆的 `autumn-apply` 文件夹；
2. 双击 **`AutumnApply.command`**；
3. 第一次运行时，启动器会在需要时运行 `npm install`，因此可能需要几分钟；
4. 随后它会构建扩展、启动本机服务、打开扩展目录和 Chrome 扩展管理页。

如果 `.command` 没有执行权限，可以先查看脚本内容，然后在终端进入项目目录并运行：

```bash
chmod +x AutumnApply.command
./AutumnApply.command
```

也可以完全使用命令行：

```bash
npm install
npm run launch
```

不要为运行本项目关闭 macOS 的整体安全保护。如果设备受单位管理，请遵循单位策略。

### 4.2 在 Chrome 中加载扩展

1. 在 Chrome 地址栏输入 `chrome://extensions`；
2. 打开右上角的 **开发者模式**；
3. 点击 **加载已解压的扩展程序**；
4. 选择项目中的 `dist/extension` 文件夹；
5. 在 Chrome 工具栏的拼图图标中固定 AutumnApply。

### 4.3 macOS 上的 AI 密钥

如果启用 BYOK AI，API Key 会保存在 macOS 钥匙串中，服务名称为 `dev.autumn-apply.api-key`。扩展不会读取或重新显示密钥。

## 5. 首次配置

加载扩展后，点击 AutumnApply 图标，再进入 **工作台**。

### 5.1 检查本机服务

工作台中的“本机服务”应显示在线。如果显示离线，请重新运行 `AutumnApply.cmd` 或 `AutumnApply.command`。

### 5.2 导入简历

进入 **个人资料库**，可以选择：

- PDF；
- DOCX；
- TXT；
- Markdown。

基础解析在本机完成，而且只补充空白字段。导入后必须人工核对姓名、联系方式、教育经历、时间、技能和项目。扫描图片型 PDF 暂无 OCR，可能无法提取文字。

### 5.3 补充个人事实

建议至少填写：

- 姓名，以及邮箱或手机号；
- 教育经历和毕业年份；
- 实习、工作或项目经历；
- 技能、证书和语言能力；
- 目标岗位、目标城市；
- 行业和企业性质偏好；
- 必须包含词和排除词；
- 常见开放题素材，如自我介绍和求职动机。

这些内容是匹配、简历生成和自动填表的事实来源。不要填写虚构经历。

### 5.4 可选：配置 BYOK AI

不用 AI 也可以完成基础搜索、规则匹配、简历重排和表单辅助。

如需 AI：

1. 在个人资料库的 **BYOK AI 增强**区域选择 OpenAI、智谱 GLM 或 DeepSeek；
2. 填写模型名称和自己的 API Key；
3. 点击 **保存 AI 配置**；
4. 点击 **测试连接**。

AI 结构化简历时会发送提取后的简历文本，不发送原始文件；语义岗位分析会移除姓名、邮箱、手机号和个人链接。OpenAI 可用于托管网页搜索；智谱 GLM 通过官方 `web-search-pro` 进行联网搜索，系统只接收该接口实际返回的链接后再核验；DeepSeek 当前用于结构化和匹配。

## 6. 搜索和筛选岗位

打开 **找岗位**，填写或检查：

- 搜索岗位，例如“管培生、合规、人力资源”；
- 工作地点；
- 必须包含词；
- 排除词；
- 最低匹配分；
- 最近天数；
- 最多返回数量。

“公众号重点词”可以填写重点公司、公众号或行业，例如：

```text
国资小新、中石油招聘、航运招聘、金融央企
```

系统会搜索已支持的企业官网和公开公众号线索。公众号每轮最多执行六个顺序查询，不并发、不重试；遇到验证码或临时限制会停止并保留已经找到的结果。

结果页会显示：

- 公司、岗位、地点和日期；
- 来源类型；
- 匹配分、优势、差距和硬性条件提醒；
- 公众号名称、文章类型和可提取的截止日期；
- 官方岗位或原始文章链接。

“企业官网岗位”和“公众号招聘信息”的可信等级不同。公众号结果始终是待核验线索，必须打开原文确认企业主体、目标届别、截止日期和真正的投递入口。

## 7. 保存搜索提醒

一次基础搜索成功后，可以打开 **自动检查新岗位**，选择每 12、24 或 72 小时检查一次。

后台监控：

- 不会自动调用或消耗 BYOK AI；
- 会提醒新发现的岗位；
- 会单独提醒七天内截止的岗位。

Chrome 关闭、电脑休眠、网络失败或来源验证码都可能导致提醒延迟，因此企业官网仍是截止日期的最终依据。

## 8. 准备申请材料

对岗位选择 **要投 · 准备材料** 后：

1. 系统建立独立的申请记录；
2. 根据岗位要求提出缺失信息问题；
3. 用户补充并确认回答真实；
4. 生成本地规则版或 AI 增强版岗位简历；
5. 人工核对每一项表述；
6. 下载 Word，或打开打印页另存为 PDF。

本地规则版只选择和重排已有事实；AI 版允许优化表达，但生成内容必须关联资料库中的真实经历来源。

## 9. 在招聘网站辅助填表

1. 从结果页打开企业的真实招聘页面；
2. 由用户完成登录、扫码和验证码；
3. 打开 AutumnApply，点击 **提取并分析**；
4. 核对识别出的公司、岗位和要求；
5. 点击 **填写当前表单**；
6. 检查填写报告和所有橙色字段。

系统不会自动填写密码、验证码、身份证、银行信息、薪资历史、法律声明、文件上传、复选框和单选框，也不会覆盖页面已有值。

如果填写不合适，可以点击 **撤销上次自动填写**。它只恢复仍然等于自动填写值的字段，不会覆盖用户之后的手动修改。

## 10. 最终提交

默认的 **审核提交** 模式永远不会点击最终提交按钮。

用户也可以只为当前岗位授权一次提交尝试。此时仍然需要：

1. 当前岗位的一次性授权；
2. 提交前安全检查通过；
3. 用户再次确认；
4. 页面只有一个明确的提交按钮。

点击按钮只会记为“已发起提交”，不代表企业网站已经接收成功。用户看到招聘网站的成功页面后，再把状态确认成“已投递”。

## 11. 日常启动和更新

### 日常启动

- Chrome 扩展首次加载后会保留；
- 电脑重启后，如果工作台显示本机服务离线，再运行一次对应平台的启动器；
- 如果服务仍在线，可以直接使用扩展。

### 使用 Git 更新

在项目目录运行：

```bash
git pull
npm install
npm run launch
```

然后进入 `chrome://extensions`，在 AutumnApply 卡片上点击**重新加载**。

### 使用 ZIP 更新

重新下载并解压新版本。如果解压到不同目录，需要在 `chrome://extensions` 中移除旧扩展，再加载新目录下的 `dist/extension`。Chrome 本地资料是否保留取决于扩展标识是否变化，因此重要资料应先在个人资料库中导出 JSON 备份。

## 12. 常见问题

### 提示找不到 Node.js

安装 Node.js 20 或更高版本，然后完全关闭并重新打开终端或启动器。

### 工作台显示本机服务离线

重新运行启动器。仍失败时，查看项目中的 `.autumn-apply-runtime/api.log`，确认 `43127` 端口没有被其他程序占用。

### 修改或更新后页面没有变化

重新运行启动器完成构建，然后在 `chrome://extensions` 中点击 AutumnApply 的**重新加载**按钮，并刷新招聘网页。

### Windows 没有自动打开 Chrome

手动打开 Chrome 和 `chrome://extensions`，然后加载启动器已经打开的 `dist\extension` 文件夹。

### macOS 无法双击 `.command`

先确认文件来自本项目并查看内容，再使用本指南中的 `chmod +x` 与命令行启动方式。不要关闭系统整体安全保护。

### 公众号搜索出现验证码或临时限制

停止重复搜索，稍后再试，或使用结果中的标题备用搜索链接进行人工搜索。AutumnApply 不会绕过验证码或模拟用户身份。

### PDF 没有识别出内容

当前只支持含真实文字层的 PDF。扫描件或图片简历需要先通过可信工具进行 OCR，再导入 DOCX、TXT 或可复制文字的 PDF。

## 13. 数据与隐私

- 个人资料、搜索结果和申请记录默认保存在当前 Chrome 配置中；
- 简历文件解析在本机服务中完成；
- 本机服务只监听 `127.0.0.1`，不向局域网开放；
- macOS 使用钥匙串保存 BYOK 密钥；
- Windows 使用当前用户 DPAPI 加密 BYOK 密钥；
- 清除或卸载前，建议先导出个人资料 JSON；
- 如果不再使用 BYOK AI，应先在个人资料库中点击**删除密钥**。

AutumnApply 不以绕过验证码、规避招聘平台限制或无人值守海投为目标。使用时应遵守招聘网站条款，并在提交前人工核对全部信息。
