# AutumnApply

面向中国校招与秋招的本地优先 AI 求职助手。

AutumnApply 的目标是把重复劳动自动化，同时把事实核对、隐私控制和最终提交决定留给求职者本人：

- 建立可复用的个人事实库；
- 从招聘页面提取并标准化岗位信息；
- 根据硬性条件和真实经历解释岗位匹配度；
- 在不虚构经历的前提下生成岗位版简历；
- 自动填写招聘网站表单；默认在最终提交前暂停，也可由用户为单个岗位授权一次提交；
- 在本地跟踪每次投递使用的简历版本和后续进度。

> 当前版本为 v0.6 可用性版本。它已经连接“导入—搜索—决策—准备—导出—填写—提交权限—跟踪”，但复杂招聘平台仍需要持续增加专用适配器。

## v0.6 已经能做什么

- 在 macOS 或 Windows 双击对应启动器，自动安装所需依赖、构建扩展、启动本机服务并打开 Chrome 扩展管理页；
- 通过统一工作台查看首次配置进度、最近搜索和申请状态；

- 根据资料库中的目标岗位、地点和技能自动生成搜索条件；
- 接收用户额外指定的岗位词、地点、必须包含词和排除词；
- 从腾讯、美团以及多个 Moka 企业官网入口读取真实岗位与任职要求；
- 通过统一适配层支持飞书招聘、Greenhouse、Lever 和 Ashby 官方入口；
- 允许用户维护额外企业官网来源清单，不把公司范围写死在代码里；
- 从搜狗微信公开结果按岗位、届别、城市、行业和用户指定的重点公众号/公司词进行最多六次低频组合搜索；对文章稳定去重、提取账号/地点/日期/截止时间、区分单企业公告与岗位汇总，并明确标注为待核验线索；
- 对搜索结果执行硬条件检查、匹配评分、解释和排序；
- 对每条结果选择“要投”或“不投”，并保存原因和申请状态；
- 在浏览器本地编辑、导入和导出个人事实资料；
- 从当前标签页提取岗位、公司、地点和职位描述；
- 检查毕业年份、学历、目标方向、技能和地点偏好；
- 给出可解释的匹配分数、优势、差距和提醒；
- 根据相关度重排真实经历，生成可下载的 Markdown 岗位版简历；
- 填写普通文本框、文本域和原生下拉框；
- 用绿色和橙色区分已填写项与人工处理项；
- 在本地记录待提交和已投递岗位；
- 通过只监听本机回环地址的服务导入 PDF、DOCX、TXT 和 Markdown 简历；
- 可选配置用户自己的 OpenAI 或 DeepSeek API Key，并将密钥保存在 macOS 钥匙串或通过 Windows 当前用户 DPAPI 加密；
- 在用户明确点击后用 AI 结构化简历、分析硬性资格和语义匹配；
- 使用 OpenAI 托管网页搜索补充公开岗位，并独立核验引用网址的可达性和正文信号。
- 为每个要投岗位建立独立准备页，提示简历缺少的事实并保存用户确认的回答；
- 在不用 AI 时按真实经历重排简历，在使用 AI 时生成带原始经历来源的改写和开放题草稿；
- 提供“审核提交”和“当前岗位一次性授权提交”两种模式；验证码、密码、缺失必填项、未处理文件或多个提交按钮都会阻止自动提交；
- 把岗位版简历导出为 Word，或打开专用打印页另存为 PDF；
- 保存 12、24 或 72 小时的基础搜索，在浏览器后台发现新岗位并提醒七天内截止的岗位；
- 识别 Moka、北森、飞书招聘、Greenhouse 和 Lever 页面，在通用安全填表后报告已填、待处理和跳过字段；
- 保存本次填表快照，在字段未被用户继续修改时支持一键撤销，并保留本地审计记录。

AutumnApply 不会填写密码、验证码、身份证、银行、薪资和法律声明，也不会覆盖已有内容。默认模式永远不点击最终提交；一次性提交只有在用户针对当前岗位授权、再次确认且安全检查通过后才会执行，执行后仍需用户确认招聘网站是否返回成功结果。

岗位发现采用来源注册表和 provider 适配器。当前内置腾讯、美团、DeepSeek、月之暗面和智谱 AI，并可添加使用 Moka、飞书招聘、Greenhouse、Lever 或 Ashby 的其他企业官方入口。公众号搜索提供补充线索：每轮最多六次顺序请求，不并发、不重试，遇到验证码或临时限制立即停止并保留已取得的结果。微信生态没有稳定的全网公开搜索 API，因此结果不代表全部中国秋招市场。v0.6 对 Moka、北森等页面的“识别”不等于完整专用适配：复杂控件、附件、重复经历和跨页流程仍会交给用户处理。

## 核心原则

1. **本地优先**：个人资料、简历和投递记录默认保存在本机。
2. **事实可追溯**：生成的每条简历内容都应能追溯到用户确认过的事实。
3. **人在回路**：登录、验证码和敏感问题由用户本人处理；最终提交默认为人工，也可以按岗位授予一次性权限。
4. **适配器架构**：通用表单引擎与北森、Moka、牛客等平台适配器分离。
5. **透明可审计**：匹配理由、自动填写结果和生成内容都可以人工复核。

```text

  api/             本地 API：解析、匹配、生成文档
  dashboard/       本地投递看板
packages/
  contracts/       各模块共享的数据契约
  form-engine/     通用表单识别与填写
  job-parser/      岗位页面解析与标准化

docs/
  architecture.md  系统设计和安全边界
  roadmap.md       分阶段开发计划
```

## 开发

要求 Node.js 20 或更高版本。

macOS 首次使用可以双击仓库根目录的 `AutumnApply.command`；Windows 可以双击 `AutumnApply.cmd`。启动器会检查 Node.js 20、在需要时安装依赖、构建扩展、启动只监听本机的 API，并打开 Chrome 扩展管理页与待加载的扩展目录。Windows 会检查系统级与当前用户级 Chrome 安装；若未找到，会打开扩展目录并提示用户手动进入 `chrome://extensions`。

两个平台的命令行等价方式都是：

```bash
npm install
npm run launch
```

开发和验证命令：

```bash
npm install
npm run start:api
npm run check
npm run typecheck
npm test
npm run build
```

### 在 Chrome 中加载

1. 运行 `npm run build`；
2. 打开 `chrome://extensions`；
3. 开启开发者模式；
4. 点击“加载已解压的扩展程序”；
5. 选择仓库中的 `dist/extension`；
6. 打开扩展设置页并建立本地资料库。

保存资料后，从扩展弹窗点击“找岗位”即可进入岗位发现页面。扩展只申请已支持招聘系统 API 与搜狗微信的精确域名权限；它只发送搜索关键词和届别，不会向岗位来源发送用户姓名、联系方式或完整简历。

扩展首页的“工作台”会显示资料完整度、最近搜索和申请状态。一次基础搜索成功后可以保存为定时监控；后台监控不会调用 BYOK AI，只使用已配置的公开来源。Chrome 关闭、扩展休眠、网络失败或来源验证码都可能延迟提醒，因此截止日期仍应以企业官网为准。

本机服务运行后，设置页可以直接导入 PDF/DOCX 简历。基础解析完全在本机完成。AI 功能默认关闭且不需要 Key；启用 BYOK 后，简历结构化会在用户点击时发送提取后的简历文本，岗位语义分析会移除姓名、邮箱、手机号和个人链接后再发送。OpenAI 配置支持托管网页搜索；DeepSeek 配置支持结构化和匹配，但不会被错误标记为具有托管网页搜索能力。

如需在不接触真实招聘网站的情况下完整试用，参见 [手动验收指南](docs/manual-test.md)。

## 开源基础

项目会优先采用许可证清晰、允许复用的开源代码，并保留必要的版权和许可证说明。初始架构参考了 OpenJobAutofill、CareerWeaver、Offer Harvester 和 czc-good-job 的公开设计；详情见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。

当前 MVP 没有复制上述项目的源代码。后续引入第三方代码时，必须在同一个改动中补充来源、版本、许可证和修改说明。

## 安全与合规

AutumnApply 不以绕过验证码、规避平台安全机制或无人值守海投为目标。自动化功能应遵守目标招聘网站的服务条款，并在对外提交或发送信息前取得用户明确确认。
